# Prototype module contract

PT_Core.lua returns global PTCore. Pure Lua, no game APIs. Coordinates use world x across court and world y along court, z is ball height above the court's floor. North/south courts only in v0.1. Court table: id string, x1,y1,x2,y2 integers inclusive boundary coordinates, z integer floor, mode `tennis` or `wall`. Width 6..14, length 12..30. Wall is north y1 edge, actual wallN collision required. Server assigns player to slot 1 (north) or 2 (south); wall player slot 1 occupies south half.

Core interface: new(court, options) -> state; serve(state,slot,px,py,aim) -> boolean; swing(state,slot,px,py,aim) -> boolean; step(state,dt); snapshot(state) -> serializable deep copy. options: gamesToWin (default2), ballSpeed(default9), hitRadius(default1.8). State includes court, phase (`ready`,`rally`,`finished`), server (1/2), points={0,0}, games={0,0}, winner(0/1/2), ball (x,y,z,vx,vy,vz, or nil), lastHit, bounces, faults, rally, bestRally, message. Internal fields allowed. Core validates serve position by baseline and alternating service side; swing by reach, height, side, cooldown via state clock. Aim integer -1/0/1 shifts target lateral position. Tennis advantage scoring, two faults, diagonal service box, net, out, two bounces. First serve net touching may be fault in prototype, documented. Wall physical reflection at north boundary above floor; no AI. Point/reset returns ready, practice bestRally retained. Server switches each completed game. Match gamesToWin is first-to-N games, no sets/tiebreak/end changes.

PT_Server.lua owns global PTServer, no work on remote client. Public dispatch(player,command,args) supports create {x1,y1,x2,y2,z,mode}, join {id}, serve {aim,seq,session}, swing {aim,seq,session}, leave {}, sync {}. PTServer.dispatch supports SP client direct calls. Sessions get fresh id and sequence protection. Client gets `PlayableTennis` commands `state` with {session,slot,revision,core,...}, `list` with {courts}, `error` with {message}, `left` with {}. state.core is Core.snapshot; players names optional. state must include lastSeq so resync recovers input sequence. Server calls PTClient.receive(command,args) in SP if available, otherwise sendServerCommand(player,...). Client uses OnServerCommand and sendClientCommand(player,...). Client create/join uses menus. Court registry persistence via ModData; active sessions never persist. Physical inventory Base.TennisRacket in primary hand and Base.TennisBall anywhere in inventory required for serve; ball is virtual and neither removed nor awarded.

PT_Client.lua global PTClient.receive. Context menu marks two corners (local draft), registers tennis or wall court, lists nearby saved courts, join/leave. UI HUD and projected world ball/shadow using native iso conversion, key press controls (defaults J swing, K serve, left/right arrow aim sampled at hit). Suppress while chat/text input active if verified API available; only process active session. Server responds each input even if rejected so HUD communicates reason. Client draws boundary/service/net lines from state court, labels slot, score, phase, guidance. No runtime file edits or copied third-party assets.
