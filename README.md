# Playable Tennis — 0.1.1 prototype

Project Zomboid B42.20+용 **플레이어 1대1 테니스 / 혼자 벽 연습** 모드입니다. AI 상대는 없습니다. 모드 ID는 `PlayableTennis`입니다.

현재 단계는 **소스와 게임 Kahlua VM에서 검증한 플레이테스트용 프로토타입**입니다. 실제 게임 화면, 2인 멀티플레이, 전용 서버 접속은 아직 검증하지 않았습니다. 42.20 전체 계열 호환성도 실기 확인이 필요합니다.

## 설치

`Contents/mods/PlayableTennis` 폴더를 각 PC의 `%USERPROFILE%/Zomboid/mods/PlayableTennis`로 복사하고 모드 선택에서 활성화합니다. `42`와 `common` 폴더를 함께 유지하세요. 개발 PC에서는 `scripts/package.ps1 -Install`로 설치·파일 해시 확인이 가능합니다.

멀티플레이는 서버와 모든 참가 클라이언트에 같은 버전이 필요합니다. 서버의 선택한 테스트 프리셋 `Mods`에 `PlayableTennis`를 추가합니다. 아직 Workshop에 올리지 않았으므로 Workshop ID는 없습니다. 이 작업은 기존 서버 프리셋이나 저장 게임을 변경하지 않습니다. 소스의 `scripts/package.ps1`은 로컬 배포만 수행합니다.

## 코트 만들기

1. 평평하고 장애물이 없는 **북–남 방향** 공간을 준비합니다. 너비(X 방향) 6–14타일, 길이(Y 방향) 12–30타일입니다. 첫 시험은 8×18 또는 8×20 야외 공간을 권장합니다. 이소메트릭 화면의 위아래가 아니라 월드 X/Y 방향입니다.
2. 월드 우클릭 → **Playable Tennis** → **Mark corner 1/2**로 대각선 두 모서리를 지정합니다. 메뉴가 `current feet (empty click)`라고 표시하면 클릭 지점 대신 현재 서 있는 타일이 선택됩니다. 모서리는 사각형 경계 좌표이며, 8×20은 두 좌표 차이가 각각 8과 20입니다.
3. **Register 1v1 court** 또는 **Register wall court**를 선택합니다. 벽 연습에는 사각형의 북쪽, 즉 작은 Y 경계 전체를 덮는 실제 벽이 필요합니다. 창문·문·울타리는 인정하지 않습니다. 별도의 물리 네트는 필요하지 않으며 내부 장애물로 검사될 수 있습니다.
4. **Refresh court list / synchronize** 후 메뉴를 다시 열고 **Join 번호**를 선택합니다. 1대1은 두 사람이 같은 코트에 참가해야 시작됩니다. 먼저 참가한 사람이 북쪽 1번, 다음 사람이 남쪽 2번입니다. 벽 연습은 1명만 참가합니다.
5. 오른손(주 손)에 정상 상태의 `Base.TennisRacket`을 장착하고, 서브하는 사람은 인벤토리에 `Base.TennisBall`을 소지합니다. 공 아이템은 소비·생성하지 않습니다.

소유자 또는 관리자는 비어 있는 가까운 코트를 **Remove** 메뉴로 지울 수 있습니다. 기본 제한은 사람당 코트 4개, 월드당 64개, 동시 세션 16개입니다. 등록 데이터는 월드에 저장됩니다.

## 조작과 규칙

| 조작 | 동작 |
|---|---|
| 우클릭 유지 + 마우스 이동 | 좌우 목표 지점 조준; 초록 십자로 표시 |
| 우클릭 유지 + 좌클릭 | 대기 중 서브, 랠리 중 스윙 |
| K | 베이스라인에서 서브 |
| J | 타이밍에 맞춰 스윙 |
| 왼쪽/오른쪽 방향키 + J/K | 월드 서쪽/동쪽으로 목표 지점 변경 |
| 우클릭 메뉴 Serve/Swing | 키 대신 동일 입력 |
| Leave court | 세션 종료; 1대1은 양쪽 모두 종료 |

마우스가 기본 조작이며 J/K와 방향키는 보조 조작입니다. 보조 키는 프로토타입에서 고정입니다. 텍스트 입력 중에는 테니스 입력을 받지 않으며, UI가 소비한 클릭으로는 스윙하지 않습니다.

**라켓을 들기만 해서는 테니스 모드가 되지 않습니다.** 코트의 Join 메뉴로 참가해야 경기 HUD가 나타납니다. 참가 중이고 경기가 끝나지 않았으며, 코트와 같은 층의 경계 2타일 이내에서 정상 라켓을 주 손에 들고 있을 때 마우스 조작이 적용됩니다. 상대를 기다리는 중과 서브 대기도 포함됩니다. 이 조건에서 우클릭을 누르는 동안 일반 공격 입력을 차단합니다. 참가하지 않았다면 라켓을 원래처럼 무기로 사용할 수 있습니다.

참가 중 같은 라켓으로 싸우려면 **Leave court**를 선택하고 마우스 양 버튼을 놓으세요. 눌렀던 테니스 클릭이 뒤늦게 일반 공격으로 바뀌지 않도록 버튼을 놓은 뒤 이전 공격 허용 상태로 복구합니다. 경기 종료·코트 범위 이탈·라켓 해제도 같은 복구 규칙을 적용합니다. 사망·연결 종료·메인 메뉴 이동 시에는 즉시 복구합니다. 다른 모드가 직접 공격 함수를 호출하거나 이미 시작된 공격 애니메이션까지 취소하는 기능은 아닙니다.

1대1은 0–15–30–40, 듀스와 어드밴티지를 적용합니다. 기본은 **먼저 2게임 승리**이며 세트제·타이브레이크는 없습니다. 게임이 끝나면 서버가 교대하지만 코트 쪽은 유지합니다. 같은 게임에서는 포인트마다 서브할 좌우 반쪽이 바뀌며 HUD에 표시됩니다. 베이스라인 1.5타일 이내에 서서 대각선 서비스 박스로 서브합니다. 리시버는 서브가 한 번 튄 뒤 받아야 합니다. 일반 랠리는 발리 또는 1바운드 후 리턴이 가능합니다. 두 번 튀거나 첫 착지가 아웃이면 득점하며, 서브 실패 두 번은 더블폴트입니다. 네트에 걸린 서브는 렛 대신 폴트로 처리합니다.

기본 타격 거리는 공의 수평 위치에서 1.8타일, 높이는 0.15–2.4입니다. 헛스윙에도 0.25초 대기시간이 있습니다. 이동은 평소 이동키를 사용합니다. 마우스로 좌우 목표 지점을 연속 조절하며, 서브는 대각선 서비스 박스 안으로 제한됩니다. 깊이와 포물선은 보조 계산하고 파워·스핀은 아직 없습니다. 서버와 모든 클라이언트에 같은 0.1.1 버전을 적용하세요.

벽 연습은 남쪽 베이스라인에서 서브하고 북쪽 벽에서 돌아온 공을 받습니다. 벽 접촉 높이는 0–2.8, 바닥 두 번 접촉 시 랠리가 끝납니다. 연속 벽 접촉 횟수와 최고 기록을 표시합니다. **실내 스쿼시 전체 규칙/천장 충돌은 구현하지 않았습니다.** 긴 코트에서는 포물선이 높으므로 야외의 12–20타일 깊이 공간부터 시험하세요.

## 샌드박스 설정

| 설정 | 기본값 | 범위/효과 |
|---|---:|---|
| Enabled | true | 테니스 전체 활성화; 끄면 진행 세션 종료 |
| AllowCourtCreation | true | false면 관리자만 코트 등록 |
| GamesToWin | 2 | 1–6게임 선취 |
| BallSpeed | 9 | 6–14 수평 속도 목표; 네트 통과를 위한 탄도 보조로 낮아질 수 있음 |
| HitRadius | 1.8 | 1.0–2.5타일 타격 반경 |

물리 설정은 새 세션에 적용됩니다. 샌드박스 이름은 한국어/영어 번역을 포함하며, 프로토타입 경기 HUD와 안내는 영어입니다.

## 알려진 범위

- 가상 공·그림자·코트 선을 화면에 투영합니다. 실제 월드 아이템이나 3D 투사체가 아니며 벽 뒤 가림·차량·좀비·천장 충돌은 없습니다.
- 실제 라켓 모델은 장착 아이템을 그대로 사용합니다. 수락된 타격은 로컬 효과음과 HUD 표시로 알리며, 전용 캐릭터 스윙 애니메이션은 아직 없습니다. 일반 공격은 호출하지 않습니다.
- 스태미나·스킬 보너스·내구도 감소·PvP 피해를 추가하지 않습니다. 안전지대나 무적 상태를 만들지도 않습니다.
- 서버가 공과 득점을 판정합니다. 클라이언트는 약 100ms 보간 표시만 하며, 높은 지연에 대한 과거 판정 보정은 없습니다. 느린 연결에서는 체감 타격 지점이 다를 수 있습니다.
- 코트/최고 기록은 저장하지만 진행 경기·점수는 재시작 후 복원하지 않습니다. 접속 종료·사망·이탈 시 세션을 종료합니다. 같은 클라이언트의 분할화면 플레이는 미지원입니다.

## 검증

`scripts/test.ps1`은 설치된 게임의 `projectzomboid.jar`에 포함된 Kahlua로 순수 규칙, 서버 어댑터, 클라이언트 입력/스냅샷 테스트를 실행하고 모든 Lua 구문과 PowerShell 구문을 확인합니다. Java 컴파일러 경로는 매개변수로 바꿀 수 있습니다. 자세한 구조는 `docs/ARCHITECTURE.md`, 실제 접속 검증 절차는 `docs/PLAYTEST.md`에 있습니다.

검증된 소스 동작과 실제 게임에서 확인한 동작은 구분해서 기록합니다. 자동 테스트 성공만으로 멀티플레이 플레이테스트 완료를 의미하지 않습니다.
